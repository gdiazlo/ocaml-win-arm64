# OCaml and opam on Windows ARM64

Experimental, working **native Windows ARM64** ports of **OCaml 5.5.1** and
**opam 2.6.1**, plus tested **Eio 1.6**, **SSL 0.7.0**, and **SQLite3 5.4.2**.
The shared toolchain, sources, archives and scripts live in `C:/ocaml-dev`
(readable and writable by every local user). Each Windows user has a private
opam root in `%USERPROFILE%\.ocaml-dev\opam-root`. No user shell profile or
system-wide OCaml installation is changed.

The compiler, runtime, opam, and generated test executables are ARM64 PE binaries,
not x86/x64 executables relying on Windows emulation. MSYS2's Bash/Make tooling
itself uses x86_64 emulation; its **CLANGARM64** compiler and libraries are native
ARM64/UCRT.

> **Delivery scope:** the original `windows-arm64` switch and bundles remain the
> validated static-linking port. A separate experimental compiler in
> **`local-dynamic/`** now supports ARM64 FlexDLL, dynamic C stubs, and native
> `.cmxs` plugins. The source-built dynamic switch (**`default`**) passes
> Dune native/ordinary-bytecode and interactive SQLite/SSL/Eio tests. Direct
> Windows and relocated-compiler tests pass; broader upstream testing required
> two retries, so reliability is still experimental.
> Neither variant is upstream-supported or production-certified.

## Set up a user (once per Windows account)

Run as that user, for example over SSH (`cmd.exe` is the default SSH shell):

```bat
powershell -ExecutionPolicy Bypass -File C:\ocaml-dev\setup-user.ps1
```

This builds the switch **`default`** in that user's own opam root: the
dynamic-linking compiler (`ocaml-variants.5.5.1+windows-arm64-dynlink`, with
ARM64 FlexDLL) plus Dune, ocamlfind, SSL, SQLite3 and Eio, and makes it the
current switch. It takes about an hour; keep the session open (closing an SSH
session stops the build). Re-running resumes; `-Test` also runs the switch
tests. The log is `%USERPROFILE%\.ocaml-dev\setup.log`.

## Use OCaml

```bat
C:\ocaml-dev\ocaml-env.cmd       :: load into the current cmd.exe / SSH session
C:\ocaml-dev\ocaml-shell.cmd     :: or: interactive CLANGARM64 Bash
```

```sh
bash scripts/shell.sh            # from Git Bash in C:/ocaml-dev
```

```powershell
. C:\ocaml-dev\scripts\env.ps1   # load into the current PowerShell session
```

All of them use the calling user's own opam root
(`%USERPROFILE%\.ocaml-dev\opam-root`), keep the current directory, and only
affect that shell: `ocaml-env.cmd` and a dot-sourced `env.ps1` modify the shell
you are already in; the Bash launchers open a new one. Inside,
`opam install <pkg>`, `dune build`, and `ocamlfind` work normally. Prefer the
Bash shell for building packages. Pass a switch name to use another switch
(`ocaml-shell.cmd windows-arm64`, `-Switch windows-arm64`). Override the
locations with `OCAML_DEV_HOME` or `OPAMROOT_DEV`.

To load OCaml automatically in every new session (including SSH), run once as
that user (`-Preview` shows the changes, `-Remove` undoes them):

```bat
powershell -ExecutionPolicy Bypass -File C:\ocaml-dev\persist-env.ps1
```

It stores `OPAMROOT`, the switch variables and PATH entries (switch, opam,
Clang toolchain appended last) in the user's environment (`HKCU\Environment`).
`opam`, `ocaml`, `ocamlfind`, `dune` and native compilation then work in any new
`cmd`, PowerShell or SSH session. MSYS2's Unix tools are not added globally, so
build opam packages that run shell scripts from `ocaml-shell.cmd`. Re-run after
`opam switch set` to follow another switch.

Fork branches: `windows-arm64` on `gdiazlo/ocaml` and `gdiazlo/flexdll`.

## Dynamic-linking work and maintained forks

See **[docs/FORKS.md](docs/FORKS.md)** for branch baselines and minimal patch
boundaries; **[docs/DYNAMIC-VALIDATION.md](docs/DYNAMIC-VALIDATION.md)** records
source-package, library, direct-Windows, relocation, and upstream results.

```sh
bash scripts/msys.sh 'bash scripts/setup-dynamic-switch.sh'
bash scripts/msys.sh 'bash scripts/test-dynamic-switch.sh'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/test-dynamic-windows.ps1
```

The dynamic build does not overwrite `local/` or the static switch/artifacts.
Do not mix old precompiled native libraries with the new compiler. Separate
fork-relative patches and source archives are generated by
`scripts/package-dynamic.sh`; binary/repository bundles by
`scripts/package-dynamic-binary.sh`. The compiler bundle includes zstd's native
runtime DLL. SDK setup also stages the native OpenSSL/SQLite runtime DLLs.

## Static switch and development scripts

The static `windows-arm64` switch is used by the development scripts
(FlexDLL bootstrap, `test.sh`, `test-dynamic.sh`). Create it in your opam root
with `bash scripts/msys.sh 'bash scripts/setup-switch.sh'`. From Git Bash in
`C:/ocaml-dev`:

```sh
bash scripts/msys.sh 'local/bin/opam.exe --version'
bash scripts/msys.sh 'local/bin/opam.exe exec --switch=windows-arm64 -- ocamlopt.exe -version'
bash scripts/msys.sh 'bash scripts/test.sh'
```

`scripts/msys.sh` sets `OPAMROOT` to your opam root (see `scripts/common.sh`),
selects the isolated CLANGARM64 tools, enters the project root, and sets the
correct Windows COMSPEC. Do not use `C:/...` entries in a Bash PATH: use
`/c/...` instead.

For example:

```sh
bash scripts/msys.sh 'local/bin/opam.exe exec --switch=windows-arm64 -- dune build --root tests/libraries -j 2'
```

Use **two jobs for compiler/libraries and one for opam's vendored build**.
The host reports 8 GB physical RAM (about 4 GB available when measured).
Sporadic Windows process-startup failures occurred in parallel builds; the
conservative job counts mitigate this, but the underlying cause is unconfirmed.

## Installable packages and artifacts

- `repository/packages/ocaml-variants/ocaml-variants.5.5.1+windows-arm64/opam`:
  source-build compiler package; successfully installed into a fresh switch.
- `repository/packages/opam-windows-arm64/opam-windows-arm64.2.6.1/opam`:
  source-build native opam package; successfully installed and executed.
- `dist/ocaml-5.5.1-windows-arm64-src.tar.gz`: patched compiler source.
- `dist/opam-2.6.1-windows-arm64-src.tar.gz`: patched opam source with vendored deps.
- `dist/ocaml-5.5.1-arm64-windows-bin.tar.gz`: relocatable compiler/runtime bundle.
- `dist/opam-2.6.1-arm64-windows-bin.tar.gz`: opam, installer, and helper binaries.
- `dist/windows-arm64-repository.tar.gz`: compiler/library package metadata and patches.
- `dist/SHA256SUMS`: archive checksums.

The repository uses local archive URLs so it can be installed immediately on this
host. `scripts/setup-switch.sh` refreshes those URLs if the project is moved;
archive checksums do not change. For publication, replace the local URLs with
hosted archives and preserve their checksums. The Dune/findlib overrides'
auxiliary files are bundled with the repository metadata.

## Rebuild from the delivered source archives

The project-local MSYS2 installation is in `tools/msys64`. Install/refresh its
build tools with:

```sh
bash scripts/msys.sh 'bash scripts/install-toolchain.sh'
```

A core MSYS2 update may terminate its shell; rerun that command if needed. Then:

```sh
bash scripts/msys.sh 'bash scripts/build-local.sh'
bash scripts/msys.sh 'bash scripts/setup-switch.sh'
bash scripts/msys.sh 'bash scripts/test.sh'
```

`build-local.sh` bootstraps the compiler from OCaml's shipped bytecode, creates a
Unix/Str static toplevel, and builds opam with vendored dependencies. No existing
OCaml or opam installation is needed. `setup-switch.sh` uses that native opam to
build the compiler package and install the libraries. It disables opam sandboxing
and depext/Cygwin setup because the isolated toolchain is already supplied.

The upstream OCaml tests require the complete clone in `sources/ocaml`:

```sh
bash scripts/msys.sh 'bash scripts/test-upstream.sh'
```

## Layout and evidence

- `sources/`: upstream checkouts, pristine references, and source builds.
- `tools/`, `downloads/`: isolated MSYS2 and downloaded bootstrap/release files.
- `local/`: directly installed ARM64 compiler/opam.
- `%USERPROFILE%\.ocaml-dev\opam-root` (per user, not in this folder): opam state and switches.
- `patches/`: small reviewable diffs against OCaml 5.5.1 and opam 2.6.1.
- `repository/`: installable compiler/opam packages and compatibility overrides.
- `tests/`: compiler, packing, C FFI, Unicode, TLS, SQLite, and Eio tests.
- `scripts/`: environment, builds, packaging, installation, and validation.
- `logs/`: complete build, package installation, and test logs.
- `docs/PORTING.md`, `docs/VALIDATION.md`: changes, limitations, and measured results.
